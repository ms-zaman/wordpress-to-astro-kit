# Route ownership

**Status:** Draft
**Owner:** Engineering
**Last updated:** <YYYY-MM-DD>
**Phase:** 04-implementation

Every route this build publishes, classified. A route absent from this table
is unclassified and should not ship.

Paths come from `migration.config.ts`; the shapes below are the kit's
defaults. Edit the table when you edit the permalinks.

| Route | Classification | Generated by | Notes |
| --- | --- | --- | --- |
| `/` | static | `src/pages/index.astro` | The `frontPage` page, or page one of the posts index |
| `%pagename%` | static | `[...path].astro` → `ContentPage` | One per `pages` entry, under its parent |
| `%postname%` | static | `[...path].astro` → `PostPage` | One per `posts` entry |
| posts index | static | `[...path].astro` → `ArchivePage` | Page one at `postsIndex` |
| category / tag / author archives | static | `[...path].astro` → `ArchivePage` | One per registry row, empty state included |
| pagination | static | `[...path].astro` → `ArchivePage` | Pages 2..N under the pagination segment |
| `/search` | static | `src/pages/search.astro` | Query runs in the browser against the static index. `noindex` always |
| `/404` | static | `src/pages/404.astro` | What a host serves for an unmatched path |
| `/search-index.json` | data | `src/pages/search-index.json.ts` | Derived from the content index |
| `/sitemap.xml`, `/robots.txt` | data | own modules | Decided by the launch switch |
| `/media-manifest.json` | data | own module | Every upload the build depends on |
| `/deployment.json` | data | own module | The build's manifest. A description, never a configuration |
| `/_redirects`, `/redirects.json` | data | `astro.config.mjs` | Generated from `content/redirects.json` |
| redirect stubs | static | `astro.config.mjs` | One meta-refresh page per rule |

Every route is static, so none needs an adapter or a hosting decision.
`/deployment.json` reports that in the build output: `build.adapter` and
`hosting.provider` are `null`, and the rendering contract fails if either
stops being.

**`/deployment.json` is served, and it describes your migration.** It lists
every content identity, every collection, every custom post type and taxonomy
key, every withheld entity, and — since provenance — the **source site's
primary keys**: the WordPress post, term and user ids each entity came from.
None of that is secret (a live WordPress install publishes its ids through
`?p=` and its REST API), and none of it is a credential, but it is a
description of the site you migrated FROM and nobody asked you whether it
should be public.

It is a route like any other, so the decision is yours and it costs one
deletion: remove `src/pages/deployment.json.ts` and the manifest stops being
published. The gates do not depend on the route — they read the file out of
`dist/`, and deleting the module removes it from `dist/` too, which is what
makes this a real choice rather than a toggle. If you want the gates and not
the exposure, exclude the file at the point of deploy instead; the route
inventory names it, so it is one line in a deploy filter.

**Indexing is the launch switch, not a per-route property.**
